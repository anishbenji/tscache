# tscache 0.1.0

The first release of `@anishbenji/tscache`: a browser cache for
timestamp-aligned time series, built for charts that scroll through history and
follow a live tail in several tabs at once.

```sh
npm install @anishbenji/tscache
```

## Highlights

- **One cache for every tab.** `createClient` runs the cache in a
  `SharedWorker` that every same-origin tab shares, and falls back to a
  dedicated `Worker`, then to the page itself. A lost SharedWorker is detected
  with a lifetime Web Lock and reported as `workerLost`.
- **The worker fetches.** A fetcher module, loaded by the worker, fetches only
  the ranges the cache neither holds nor already has in flight, widened by one
  interval where a miss meets cached data so the series joins up (that edge
  point is fetched again). Under the
  SharedWorker hosting, concurrent reads of a range from several tabs wait on
  one fetch, and finalized history one tab fetched is not fetched again for
  another; the dedicated and in-process fallbacks give each tab a cache of its
  own. Points at or after the `finalizedUntil` watermark are provisional and
  fetched again by every read that includes them. An `AuthInvalidError`
  reaches every tab the worker serves as `authInvalid`. `updateAuth` supplies
  new credentials and fetching resumes; the application reads again any range
  that came back `'auth-pending'`.
- **Known gaps are first-class.** A read returns the present points as one
  typed array per field, the ranges the cache knows for certain, and each
  missing range with its reason. A confirmed gap is never fetched again.
- **Honest freshness.** A watermark keeps the provisional tail refetched, a
  dataset version change clears a cache, and `invalidate` and `clear` forget
  data on the application's clock. There is no TTL.
- **Strict field values.** A put or a fetcher response whose values a field
  cannot hold (`null`, a string, a fraction in an integer field, a value
  outside the dtype's range) is rejected whole, never coerced; `PutError`
  names the offending field in `offenderField`. Float fields accept `NaN`
  for a missing value.
- **Server rendering.** `encodeSnapshot`, `decodeSnapshot` and `hydrate` carry
  a server's read into the browser's cache, confirmed gaps included.
- **Persistence.** `persist: true` keeps a cache's history in IndexedDB when
  the SharedWorker hosts it.

## Entries and sizes

Each entry bundled on its own with the chunks it loads, minified and
compressed with brotli, as measured by `bun scripts/size.ts` on the release
build. A row marked _lazy_ is code the entry loads with `import()` only on the
path that needs it: the page's fallback to a worker-less engine, and the
worker's persistence.

| Entry                           | For                                                       | Brotli   |
| ------------------------------- | --------------------------------------------------------- | -------- |
| `@anishbenji/tscache`           | the page: `createClient`, the types, errors and snapshots | 4.57 kB  |
| ↳ lazy: in-process hosting      | loaded only when neither worker hosting starts            | 12.16 kB |
| ↳ lazy, nested: clear-only call | loaded by the in-process hosting at its first `clearAll`  | 5.38 kB  |
| `@anishbenji/tscache/worker`    | the worker script the application serves                  | 13.34 kB |
| ↳ lazy: persistence             | loaded at the first persisted cache, or `clearAll`        | 5.38 kB  |
| `@anishbenji/tscache/fetcher`   | the fetcher module: its types and `AuthInvalidError`      | 0.17 kB  |
| `@anishbenji/tscache/engine`    | the engine without a worker, for Node and tests           | 9.86 kB  |
| `@anishbenji/tscache/vite`      | the `fetcherUrl()` Vite plugin (runs in Node)             | 1.20 kB  |

The package is ESM-only and has no runtime dependencies. Vite 8 is an optional
peer dependency, needed only for `@anishbenji/tscache/vite`; the package
declares Vite 8's Node range (`^20.19.0 || >=22.12.0`) in `engines`. A local
`npm pack --dry-run` of this release reports a tarball of 27 files, 76.5 kB
packed and 255.2 kB unpacked; npm counts 1,000 bytes to the kB, while the
table above counts 1,024.

## Known limits

Three limits of 0.1.0 that an application has to design around, each with its
workaround in the guides:

- **Memory is neither bounded nor reported.** A cache keeps everything it was
  asked for until its worker ends
  ([Memory](https://anishbenji.github.io/tscache/guides/patterns#memory)).
- **A deploy can leave tabs on two versions.** Old and new tabs may run
  separate SharedWorkers, or `createClient` may reject with
  `ProtocolMismatchError` or `ConfigError` until the old tabs close
  ([Stale scripts after a deploy](https://anishbenji.github.io/tscache/guides/workers#stale-scripts-after-a-deploy)).
- **Readers are not told when data changes.** A view that must redraw reads
  again
  ([Redrawing when the cache changes](https://anishbenji.github.io/tscache/guides/live-feeds#redrawing-when-the-cache-changes)).

## Stability

tscache follows semantic versioning within 0.x: a minor release may break the
API, a patch release never does. Pin a minor range (`~0.1.0`) to take fixes
without breaking changes.
