# tscache 0.2.0 (in preparation)

Not released yet: these notes collect what the next release adds, step by
step, until it is cut.

```sh
npm install @anishbenji/tscache@~0.2.0
```

## Highlights

- **Change events.** A view can now follow its cache: `cacheChanged` reports,
  once per call that changed a cache, where a read's result may have changed.
  `written` lists what a put, a fetch or a hydrate wrote, the forming bar
  included; `removed` the coverage an `invalidate` or a watermark moved back
  withdrew; `cleared` a clear, a `clearAll` or a new dataset version;
  `requestId` the call that caused it. With a SharedWorker every listening tab
  hears every tab's change, the writer's own included, before the writing call
  resolves. Listen with `client.on('cacheChanged', fn)` for every cache or
  `cache.on('cacheChanged', fn)` for one; the first listener subscribes the
  client in the worker, so a page that does not listen costs nothing. Re-read
  by the documented rule: from the cache alone after an event that wrote
  something, with a fetch only after one that withdrew coverage or cleared,
  which keeps a live tail from fetching in a loop
  ([Change events](https://anishbenji.github.io/tscache/concepts/events#change-events)).
  The integrations follow their cache with at most one read per animation
  frame, and the reference clients redraw from `cacheChanged` instead of a
  `BroadcastChannel` message in the SharedWorker hosting.
- **`client.features`.** The worker's hello now lists the optional features it
  offers. A client facing a worker script from before change events (a stale
  cached script during a deploy) sees no `'cacheChanged'` there, its listeners
  are never called, and a development build warns once.

## Compatibility

- The protocol stays at version 1: the new ops and the hello's `features` are
  additive, so an older page and a newer worker, or the reverse, still connect
  (architecture N79).
- `TscacheClient` gains the readonly `features` member, and `ClientEvents` and
  `CacheEvent` gain `cacheChanged`. Code that implements `TscacheClient` itself,
  such as a test double, must add `features`.
- `hydrate` now sends `cacheChanged` for what it applied; it still sends no
  other event (architecture N77).
- Brotli sizes grow: `index` 4.61 to 5.00 kB, the in-process hosting 12.12 to
  12.71 kB, `worker` 13.34 to 13.97 kB, `engine` 9.86 to 10.10 kB.

## Known limits

- With a dedicated worker or in-process, each tab has a cache of its own and
  hears only its own changes; another tab's data must still be sent.
- After a fetch brings a new dataset version, other tabs show misses outside
  the range that fetch wrote until their next ordinary read: the price of a
  read rule that cannot loop.
- Memory is still neither bounded nor reported, and a deploy can still leave
  tabs on two worker versions (findings M3 and M5).
