# N123: The start of a day slot whose local date the zone skipped (G18)

Row N123 of the decision table in `docs/architecture.md` §8, whose introduction says how its rows were taken. Recorded in step 129 from the calendar grid design proposal (`docs/design/calendar-grid.md`, row G18), which keeps the alternatives in full. Decisions are locked (`AGENTS.md`); the architecture section lists every decision with a one-line summary.

## Resolution

**One millisecond before the next slot's start.** Slot numbering stays the calendar's, whatever the zone's rules, so page keys are stable across rule changes; a slot's start is N111's instant for it, unless that instant is not before N111's instant for the next slot, and then it is one millisecond before that. The rule is stated on instants and looks one slot ahead, so `startOf` is strictly increasing for any zone data whose offsets are each under a day, and a start takes two resolutions. In today's zone data it applies exactly to the slot of a skipped date (Pacific/Apia has no 2011-12-30, Pacific/Kwajalein no 1993-08-21): a real but empty slot, over which a fetch records a gap, as for a holiday. Rejected: numbering slots by the local dates that exist (a rule change would renumber every later slot, so persisted page keys would misplace points); treating the slot as a hole in the domain (a chart scrolling across it would fail); refusing zones that skip a date (needs a scan of the domain per zone, and shuts those zones out). The cost: one instant per skipped date is aligned although no clock showed it. User decision 83, row G18 option (b), 2026-11-21 (§4.1, step 129)
