# N57: Load atomicity

Row N57 of the decision table in `docs/architecture.md` §8, whose introduction says how its rows were taken. The text below is that row, moved here unchanged in step 73. Decisions are locked (`AGENTS.md`); the architecture section lists every decision with a one-line summary.

## Resolution

**Memory is canonical: a load applies records only into a cache that knows nothing, and any change while the load is pending abandons it.** `cache()` resolves after the load, so no handle reaches the cache before it (unchanged, user-confirmed 2026-10-30). What arrives by cache id meanwhile (another tab's `clearAll`, a raw request, an `Engine` driven directly) abandons the load: nothing stored is applied, and the cache's next flush rewrites its records from memory. `CacheState.restore` throws when the cache holds any coverage or point, so no path reconciles stored and live data of one slot. Round 3 (R3-2) found the abandon signal incomplete, since a put wholly inside the volatile region reports no change: a separate hook, `onMutate`, now fires for every mutating call that passed validation, so the rule reads "any mutating call abandons the load". **Changed in substance after review round 2.** The first design filled only what memory did not know, behind a fence of what changed meanwhile; round 1 (R1-1) found it overwriting a provisional point under a higher stored watermark, and round 2 (R2-1) found the patched skip leaving the skipped authority on disk, since nothing marked it dirty. Both are the same cause: a slot-level merge of two authorities while one of them keeps changing, whose result is never written back. Weighed and rejected: holding every op on the cache in the RPC server until the load ends (a per-cache queue in the server for a case handles already prevent; `clearAll` would wait up to 5 s and then still have to undo what the load wrote; the load of about 16 pages takes 6.8 ms, so the handle wait of `cache()` already costs nothing noticeable); a monotonic epoch in the cache record with pages ignored unless their epoch matches (one more field and rule to get what the full rewrite's single transaction, which deletes and puts atomically, already gives); applying stored records as a ranged `put` (overwrites newer data). Cost accepted: a cold start when a cache is changed during its load, which ordinary use cannot reach. Redesign, 2026-10-30
