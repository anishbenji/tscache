# N68: Field values a put accepts

Row N68 of the decision table in `docs/architecture.md` §8, whose introduction says how its rows were taken. The text below is that row, moved here unchanged in step 73. Decisions are locked (`AGENTS.md`); the architecture section lists every decision with a one-line summary.

## Resolution

**Only values the field can hold; anything else rejects the whole batch with `PutError` `'field-mismatch'`.** Every `put` batch and every fetcher response (they share the path) is checked in batch validation, after the timestamps and the range and before anything changes, field by field in schema order; the first offender is named by field (`offenderField`, added as specified: a director decision under the user's grant, 2026-11-10, open to the user's veto), index, timestamp, value and what was expected. A value that is not of type `number` (`null`, `undefined`, a sparse-array hole, a string, a boolean, a bigint, an object) is never coerced. Float fields accept every number, `NaN` and `±Infinity` included, so `NaN` stays the missing-value marker of a present point (§2.4); integer fields accept only integers inside the dtype's range (`-0` and `2.0` included) and reject fractions, `NaN`, `±Infinity` and out-of-range values. A typed array of the field's own dtype is not scanned. Why: a JSON backend sends `null` for a missing value, which typed-array assignment stored as `0`, a zero-price bar indistinguishable from data, and `300` in a `u8` field was stored as `44` and `-1` as `255`, with no error and no warning (November 2026 review, §3i); tightening this after 0.1.0 would be a breaking change. Cost: one pass over each `number[]` and each typed array of another element type; the performance and size budgets hold. Fractions in integer fields are rejected, not truncated, by user decision 38 (option B, 2026-11-10): loosening later is non-breaking and tightening is not; measured with the Bun bench gate against truncation (option A), the cost is within noise (put cases 0.99–1.07 against `main` for both, none near the 1.10 threshold; the `index (lazy)` entry 8 bytes smaller). Rejected: mapping `null` to `NaN` for float fields and rejecting it for integer ones (friendlier to JSON backends, but hides what the backend sent); documenting the coercion only (no cost, but a zero-price bar stays silent); truncating a fraction in an integer field (decision 38, option A: the earlier documented conversion, but it loses data silently and could only be tightened later as a breaking change).
