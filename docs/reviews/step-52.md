# Step 52 — `clearAll` empties the disk from every hosting

Branch: `feat/52-clear-other-hostings` · Reviewer: Codex, round 1 · Status: round 1 fixed, awaiting re-review · Verdict after triage: —

## Scope

User decision #11 (1), option (b), 2026-11-02 (`~/code/tscache-reports/decisions-resolved.md`, entry 11): a `clearAll` from a page whose client is hosted in a dedicated worker or in-process, the hostings that do not persist (N52), must also empty the IndexedDB database with a clear-only call, so records persisted earlier by a SharedWorker session cannot reappear. It replaces D24 of step 38 (option (a), "the disk left alone"). The user's constraints: built test-first; the clear-only code in the lazy persistence chunk, never in the initial load; a failed clear turns persistence off as D27 does, with what "off" means for these hostings designed here and flagged; no database is created where there is none; no other locked decision changes.

## Decision concerns

For the director, each taken with the recommended option:

1. **D52-1, the failure rule (N66).** "Off" means nothing more for a hosting that does not persist. If the director wants a later SharedWorker protected after a failed clear, the only mechanism found is a durable marker, which fails when the disk refuses writes and needs a layout change (N51).
2. **D52-2, no latch after a failed import**, unlike I19 in the SharedWorker.
3. **No event on a failed clear-only call.** An app in these hostings cannot learn that its logout left records on disk. A SharedWorker that tracks no persisted cache is equally silent; giving both a signal would be a new public event or reason, a decision for the user.
