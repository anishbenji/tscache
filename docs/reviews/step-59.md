### Mermaid plugin compatibility

`vitepress-plugin-mermaid` 2.0.17 is the latest release; it declares `vitepress: ^1.0.0 || ^1.0.0-alpha`
as a peer, so `bun install` warns about vitepress 2.0.0-alpha.21. It works with it: the plugin's Vite
transform registers its component by inserting a line before the first `app.component(` call in
`vitepress/dist/client/app/index.js`, and alpha.21's file still has those calls
(`app.component("Content", Content)`). The site builds, and the graph renders in Chromium in both themes
(below). Its other peer, `mermaid`, accepts `10 || 11`; 11.17.2 is the newest 11.x (published
2026-08-25). The plugin re-renders a diagram with Mermaid's `dark` theme while the page's root element
has the `dark` class.

Cost: the plugin registers its component for every page, so every page now preloads Mermaid's core
chunks. The index page preloads 856 KB of JavaScript (minified) after this change; of the chunks it
preloads, the Mermaid ones (`chunk-*`, `rough.esm`, `d3-selection`, `dist`) add about 110 KB gzipped.
Mermaid's per-diagram chunks (flowchart, sequence, …) still load only on demand.

### The module graph script

`site/scripts/module-graph.ts` starts at the files `packages/tscache/package.json` exports (mapped to
`src/entries/<name>.ts`), follows every relative import with Bun's transpiler (`Bun.Transpiler.scanImports`,
which drops type-only imports), and writes a Mermaid flowchart and a per-entry table between two marker
comments in `site/how-it-works/package-map.md`. With `--check` it rewrites nothing and exits 1 when the
region differs; `bun run docs:check` runs it. The table is padded as Biome formats Markdown tables, so
`biome ci` and the check agree.

Checked: removing one edge line from the region makes `--check` exit 1 with "out of date"; restoring it
makes it exit 0. The generated "bundles" column agrees with the built chunks: `dist/index.js` imports
`errors`, `lifetime`, `port-client`, `snapshot`, `types` chunks and `import()`s `in-process-*.js`, which
imports the engine and server chunks and `import()`s `lazy-*.js`; `dist/worker.js` imports the engine,
lifetime and server chunks and `import()`s `lazy-*.js`.

| A segment leaves the engine as a `DenseSegmentPayload` (first timestamp, slot count, grid, mask, little-endian buffers)                                                                       | `types.ts#DenseSegmentPayload`, `segment/payload.ts#segmentFromPayload`                                                                                    |
| A `Snapshot` wraps the payloads with coverage, version and watermark                                                                                                                          | `types.ts#Snapshot`, `engine/snapshot.ts#takeSnapshot`                                                                                                     |
| `get(range, { snapshot: true })` returns one; the persister stores one per page                                                                                                               | `engine/cache.ts#CacheState` (`get`), `persist/records.ts#PageRecord` (`snapshot`)                                                                         |
