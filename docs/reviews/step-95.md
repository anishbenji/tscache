# Step 95 — The flaky tests

Branch: `fix/95-flakes` · Reviewer: none yet (the director reviews) · Rounds: 0 · Status: built · Verdict after triage: pending

## Scope

Four tests failed intermittently on the development machine, whose load average has reached 100 to 280 from processes outside the project. Each failure was traced to a test depending on timing or ordering it did not control. None is a defect in `packages/tscache/src` or in the reference code. The fixes follow `docs/testing.md`: each test now waits for the condition it needs, or holds back the event it must order. No timeout was raised, no retry added and no assertion weakened.

## Verification

Load was added with one busy loop per core (`yes`, ten cores), as `scripts/flake-hunt.sh --load` does. Playwright ran with `--repeat-each`, one worker and no retries, through `~/code/tscache-reports/bin/heavy-run.sh`. The load averages are those `uptime` printed before and after each run.

**Reproductions.** The failures did not recur by repetition at the load reachable here (the baseline below). Each cause was therefore reproduced deterministically, by forcing the ordering that a loaded machine produces:

The first after-fix run, before the Retry wait was added, passed 134 of 140: R1-3 failed 3 times ("fetch failed: 1 range" after Retry: twice on reference-solid, once on reference-vanilla), and 3 tests did not run after them. Load was 13.3 before and 26.8 after. `scripts/flake-hunt.sh -n 20 --load scripts/demo/processes.test.ts` passed in that run: 0 failures in 20 runs, 120 tests, load 26.8 before and 23.4 after.

Other checks: `bun run typecheck` exit 0; `bun scripts/test-clocks.ts` "166 files clean"; `bunx vitest run examples/mock-backend/test/backend.test.ts` 17 passed; `bunx biome check` on the changed files, no fixes.

Not shown: the after-fix runs did not reach the load averages of 100 to 280 seen on this machine; the load averages observed here ranged from about 5 to 72. The fixes do not depend on load: each removes the ordering or timing the test relied on. The three reference-spec causes fail on every run when that ordering is forced; the processes cause failed 1 run in 5 with the shortened lifetime, because the old test still raced the child's exit rather than forcing it.
