## Scope

Four tests failed intermittently on the development machine, whose load average has reached 100 to 280 from processes outside the project. Each failure was traced to a test depending on timing or ordering it did not control. None is a defect in `packages/tscache/src` or in the reference code. The fixes follow `docs/testing.md`: each test now waits for the condition it needs, or holds back the event it must order. No timeout was raised, no retry added and no assertion weakened.

Two drafts of the fix failed in these runs and were replaced. A drag whose halves were single moves did not pan: Lightweight Charts 5.2.1 takes moves within 5 px of the press for a click, and of the moves after that the first marks where the drag starts and the second starts the scroll without panning. A draft with two small moves first passed 9 of 9 and failed once in 60 on reference-react, with the chart not moved at all; under load the browser may merge mouse moves, and the press may come before React has mounted the chart. The final drag waits for the chart's first draw, takes seven steps a half, and identifies each read by its reach rather than by counting moves.

Other checks: `bun run typecheck` exit 0; `bun scripts/test-clocks.ts` "170 files clean"; `bunx vitest run examples/mock-backend/test/backend.test.ts` 18 passed; `bunx biome check` on the changed files, no fixes.

Not shown: the after-fix runs did not reach the load averages of 100 to 280 seen on this machine; the load averages observed here ranged from about 5 to 72. The fixes do not depend on load: each removes the ordering or timing the test relied on. The three reference-spec causes fail on every run when that ordering is forced; the processes cause failed 1 run in 5 with the shortened lifetime, because the old test still raced the child's exit rather than forcing it.
