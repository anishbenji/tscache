## Decisions taken

- **Grid recipes** follow user decision #32, option A (resolved by the user 2026-11-10): recipes now, no API change.
- **Monthly bars:** the ordinal is the month count since January 1970 on a grid of interval 1, so every range, watermark and timestamp of that cache is an ordinal. The page states the trade-off.
- **Jittered samples:** the snippet floors late-only samples and keeps the last per slot; the page names rounding for two-sided jitter and a mean or sum as other choices.
- **`null` to `NaN` in the JSON fetcher snippet** applies to every field: a fetcher does not know the dtypes, and an integer field stores `0` for `NaN` and for `null` alike.
- **N38:** only the `./engine` export was added to the row; see "Not changed".
- **`docs/review-checklist.md` is corrected on this branch**: one line, a factual correction (review D3: the checklist asked reviewers to check for a retry the code deliberately lacks, approved at step ⑪). It changes what is checked, not how the review workflow runs.
- **Branch name `docs/71-…`** follows the director's brief and earlier documentation steps (`docs/42`, `docs/56`, `docs/59`).

## Where the review and the code disagree

- **Safari 15.0–15.3 and worker-loss detection** (review §4.4: no Web Locks, "so worker-loss detection (N32) is absent there"). The lock watch runs only in the shared hosting (`src/client/hosting.ts` `openShared`; architecture §4.7: "Dedicated and in-process hostings hold no lock"), and Safari has `SharedWorker` only from 16. Safari 15.x runs the dedicated hosting, which learns of a failed worker from its `error` event (`openDedicated`). Every browser version in the table that runs a module `SharedWorker` also has Web Locks in workers. The support section says this instead.
- **D14's "since N62":** the per-`get` rule was replaced by §4.9.1 rule 7, committed with N31 and N62–N65 together; the edit cites the rule and step 44.
