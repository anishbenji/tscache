## Decisions taken

- **Decision 32 is still listed as pending** in `tscache-reports/pending-user-decisions.md` (#32). The recipes follow its recommended option A as the director's brief instructs: recipes now, no API change.
- **Monthly bars:** the ordinal is the month count since January 1970 on a grid of interval 1, so every range, watermark and timestamp of that cache is an ordinal. The page states the trade-off.
- **Jittered samples:** the snippet floors and keeps the last sample per slot; the page names rounding and a mean or sum as the alternatives.
- **`null` to `NaN` in the JSON fetcher snippet** is applied to every field: a fetcher does not know the dtypes, and an integer field stores `0` for `NaN` and for `null` alike, so the mapping changes nothing there.
- **N38:** only the `./engine` export was added to the row; see "Not changed".
- **Value-conversion text** also went into `site/guides/patterns.md` and `site/guides/fetcher.md`, the pages a site reader reaches first.

## Where the review and the code disagree

- **Safari 15.0–15.3 and worker-loss detection** (review §4.4: "no Web Locks, so worker-loss detection (N32) is absent there"). The lock watch runs only in the shared hosting (`src/client/hosting.ts:120-131`; architecture §4.7: "Dedicated and in-process hostings hold no lock"), and Safari has `SharedWorker` only from 16. Safari 15.x therefore runs the dedicated hosting, which detects a failed worker from its `error` event (`hosting.ts:161-163`). Every browser version in the table that runs a module `SharedWorker` also has Web Locks in workers. The support section says this instead.
- **D14's "since N62":** the per-`get` rule was replaced by §4.9.1 rule 7, committed with N31 and N62–N65 together (56e9477); the edit cites the rule and step 44, not N62 alone.
