# Mutation testing of the engine

How well the engine's tests catch injected defects, measured with [Stryker](https://stryker-mutator.io/) on 2026-11-13 (step 84). Stryker changes one small piece of the source at a time (a mutant: `<` for `<=`, a condition forced to `true`, a call removed) and runs the tests that cover it. A mutant the tests fail on is killed; one they pass on survived, and marks behaviour no test pins down.

This is a measurement, not a gate: no CI job, hook or workflow runs Stryker, and no threshold fails a build. The survivors listed below are the input for later steps; step 84 changes no test.

## Scope

The folders the test-first rule names (`AGENTS.md`, TDD): `packages/tscache/src/grid.ts`, `coverage.ts`, `segment/`, `engine/`, `orchestrator/` and `persist/`, 4,459 mutants in all. Each mutant runs against the package's own Vitest suite (`packages/tscache/test`, under Node), narrowed by Stryker's per-test coverage to the tests that reach the mutated code. Tests in `examples/`, `reference/`, `integrations/`, `e2e/`, `scripts/` and `site/` do not count, even where they would kill a mutant.

## What the survivors are

The 483 surviving or uncovered mutants fall into four kinds. Telling them apart is what makes the list useful:

- **Unasserted error messages** (57, of which 54 survived and 3 had no coverage). An error message replaced by `""` survives because the tests check the error's class and fields, not its text. The messages are part of the developer experience, not of any contract, so most of these are acceptable; a few message tests for the validation errors a user is most likely to see would kill them. Stryker reports 75 surviving or uncovered string mutants in all; the other 18 are literals the logic compares or returns, and count as real gaps below.
- **Redundant guards** (equivalent mutants). A check whose case a later check also rejects, with the same error class. Removing it changes nothing a test can observe, and no test could. Examples: `typeof value !== "number" ||` in front of `Number.isSafeInteger(value)` (`engine/validate.ts:18`, `:39`), and the duplicate-name check in `segment/payload.ts:89`, whose case `checkFields` rejects next as a missing field.
- **Choices that only performance sees.** Which segment a merge keeps, or whether a range list is sorted when its callers already pass it sorted. The correctness suite cannot see these; the bench can.
- **Real gaps.** Behaviour a test reaches but does not check, or code no test reaches. The list below is mostly these. They include the 18 logic string literals (12 survived, 6 without coverage): state and kind values in `orchestrator/orchestrator.ts:218`, `:647`, `:693`, `:725`, `engine/cache.ts:404`, `persist/persister.ts:287`, `:313`, `:377`, `:579` and `persist/hosted.ts:150`, `:208`; the dtype prefix `"f"` in `engine/batch.ts:315`; the `typeof` operand `"string"` in `orchestrator/orchestrator.ts:64` and the request-id default in `:682`; and the four `"Error"` name fallbacks (`orchestrator/orchestrator.ts:67`, `persist/hosted.ts:49`, `persist/persister.ts:125`, `:129`).

## How to re-run

The step 84 numbers were measured on 2026-11-13 in a throwaway copy of the worktree with the two packages installed there, because Stryker is not yet a dependency of the repository; adding it is pending user decision 60.

Once the dependencies are added (`@stryker-mutator/core` and `@stryker-mutator/vitest-runner`, 10.1.1, pinned exactly in the repository's `package.json` and `bun.lock`), run Stryker from the repository root. A run is a heavy job: run it under the heavy-job lock, never next to `bun run ci`. Every area takes about 40 minutes; `--mutate` limits a run to one area.

```sh
~/code/tscache-reports/bin/heavy-run.sh "mutation" bunx stryker run          # every area
~/code/tscache-reports/bin/heavy-run.sh "mutation" bunx stryker run \
  --mutate "packages/tscache/src/engine/**/*.ts"                              # one area
```

The configuration is `stryker.config.json` at the repository root. It runs Vitest with `vitest.mutation.config.ts`, which is the root configuration narrowed to `packages/tscache/test`, and writes `reports/mutation/mutation.html` and `mutation.json`, which `.gitignore` covers along with Stryker's sandboxes (`.stryker-tmp/`). Two settings work around the toolchain:

- `plugins` names `@stryker-mutator/vitest-runner`, because Bun installs each package in isolation and Stryker's default plugin search finds nothing next to its core.
- `tsconfigFile` names a file that does not exist, which turns off Stryker's tsconfig rewrite. The rewrite calls the TypeScript JS API, which TypeScript 7 does not ship. It only fixes paths that would leave the sandbox, and the sandbox holds the whole repository, so none do.

The numbers depend on the suite and on Stryker's version. Compare runs only at the same Stryker version.
